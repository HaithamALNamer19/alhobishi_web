# متجر - منصة التجارة الإلكترونية المتطورة (جملة وتجزئة)

منصة تجارة إلكترونية متكاملة، فائقة السرعة، ومصممة بأحدث معايير الأمان وقابلية التوسع (Clean Architecture & Feature-Based Architecture) بالريال اليمني (YER) وبواجهة عربية كاملة (RTL).

---

## 🌟 الميزات الجوهرية المنفذة

### 1. أنواع المستخدمين والصلاحيات الآمنة (Role-Based Access Control)
- **عميل عادي (Customer):** يرى أسعار التجزئة فقط ويسجل تلقائيًا عند إنشاء الحساب.
- **تاجر جملة معتمد (Wholesale Customer):** يرى أسعار الجملة المخفضة المخصصة للتجار فقط. يتم ترقيته حصريًا بواسطة المدير.
- **موظف تجهيز (Staff):** يمتلك شاشة خاصة لتجهيز الطلبات وتحديث كميات الأصناف وتأكيد الجهوزية.
- **مدير النظام (Admin):** صلاحيات كاملة لإدارة الأقسام، المنتجات، المتغيرات، الأسعار، ترقية العملاء، واعتماد الفواتير في دفتر الأستاذ المالي.
- حماية أمنية صارمة: لا يتم إرسال أسعار الجملة في ردود المتصفح إطلاقًا للمستخدمين غير المصرح لهم.

### 2. المتغيرات المتقدمة والمخزون الذكي (Product Variants & Inventory Matrix)
- دعم تركيبات لا محدودة من الخصائص (ألوان، مقاسات، خامات، موديلات).
- توليد معرّفات فريدة حتمية (Deterministic Variant IDs):
  `color-red__size-large` بغض النظر عن ترتيب الاختيار.
- خوارزمية ديكارتية (Cartesian Generator) لتوليد جدول التركيبات بضغطة زر في لوحة التحكم.
- تتبع دقيق للمخزون على مستوى كل متغير:
  - **المخزون الفعلي (Stock Quantity)**.
  - **الكمية المحجوزة للطلبات (Reserved Quantity)**.
  - **الكمية المتاحة للبيع (Available Quantity = Stock - Reserved)**.
- واجهة مستخدم تفاعلية تخفي أو تعطل الخيارات المنتهية وتمنع اختيار أو بيع كميات تتجاوز المتوفر.

### 3. دورة حياة الطلبات وحجز البضائع (Order Lifecycle & Reservations)
- دورة الطلب:
  `DRAFT` ➔ `PENDING` ➔ `PREPARING` ➔ `PARTIALLY_READY` ➔ `READY` ➔ `CONFIRMED`
- **حجز فوري للبضاعة في المستودع:** يتم حجز الكميات داخل معاملة ذرية (Firestore Transaction) لمنع البيع الزائد (Overselling).
- **مرونة تعديل الفاتورة بواسطة العميل:**
  - يستطيع العميل زيادة الكميات، تقليلها، أو حذف أصناف طالما أن الطلب في حالة `PENDING` أو `PREPARING` أو `PARTIALLY_READY`.
  - تنبيه فوري لموظف التجهيز عند قيام العميل بتعديل طلب قيد التجهيز.
- **قفل الفاتورة:**
  - بمجرد ضغط موظف التجهيز على "تأكيد الجهوزية (Mark as Ready)"، يتم قفل الفاتورة نهائيًا في الواجهة وقواعد الأمان البرمجية، وخصم المخزون الفعلي، وإشعار العميل.

### 4. الحساب المالي ودفتر الأستاذ (Customer Financial Ledger)
- لكل عميل حساب مالي مستقل بالريال اليمني (أرقام صحيحة بدون كسور).
- بعد تجهيز الطلب واعتماده من المدير (`CONFIRMED`):
  - تتحول قيمة الفاتورة تلقائيًا إلى مديونية مقيدة في جدول `accountTransactions`.
- إمكانية تسجيل سندات القبض والدفعات النقدية والحوالات وتحديث رصيد العميل فورًا.
- كشف حساب كامل متاح للعميل في لوحة حسابه.

### 5. نظام الإشعارات والتنبيهات (In-App Notifications)
- إشعارات فورية بحالة الطلب، بدء التجهيز، جهوزية الفاتورة، ترقية الحساب لتاجر، وسندات القبض.

## 🛠 التقنيات المستخدمة

- **Framework:** Next.js 16 (App Router + Turbopack + Partial Prerendering)
- **Language:** TypeScript 5 (Strict Mode)
- **Styling:** Tailwind CSS v4 (RTL First)
- **Backend & Database:** Firebase Admin SDK + Cloud Firestore (Transactions & Batches)
- **Authentication:** Firebase Auth (Session Cookie `__session` HTTP-Only)
- **Validation:** Zod
- **Testing:** Vitest
- **Icons & UI:** Lucide React, Sonner (Toasts)

## 📁 هيكلية المشروع (Clean Architecture)

```
src/
├── app/                      # مسارات Next.js App Router (29 مسارًا مجمعًا)
│   ├── (auth)/               # تسجيل الدخول وإنشاء الحساب
│   ├── account/              # لوحة تحكم العميل (الطلبات، كشف الحساب، الإشعارات)
│   ├── admin/                # لوحة الإدارة (التجهيز، المنتجات، الأقسام، العملاء، المدفوعات)
│   ├── c/[slug]/             # استعراض منتجات القسم
│   ├── p/[slug]/             # تفاصيل المنتج ومحدد الخيارات الذكي
│   ├── cart/                 # سلة المشتريات والتحقق من الأسعار والمخزون
│   ├── checkout/             # تأكيد حجز البضاعة
│   └── page.tsx              # الصفحة الرئيسية
├── core/                     # النواة المشتركة وقواعد العمل
│   ├── auth/                 # الصلاحيات والأدوار (Roles & Permissions)
│   ├── domain/               # العملة اليمنية (Money YER)، التواريخ، الهواتف
│   ├── errors/               # رموز ورسائل الأخطاء المعربة
│   └── text/                 # تطبيع النصوص العربية ومفاتيح البحث
├── features/                 # الوحدات الوظيفية (Feature-Based)
│   ├── accounting/           # دفتر الأستاذ وسندات القبض
│   ├── auth/                 # الجلسات وتسجيل الدخول
│   ├── cart/                 # السلة وحساب التكلفة بحسب الرتبة
│   ├── categories/           # الأقسام
│   ├── inventory/            # حركات المستودع وتعديل المخزون
│   ├── notifications/        # الإشعارات
│   ├── orders/               # الطلبات، محطة التجهيز، وحجز المخزون
│   ├── products/             # المنتجات، المتغيرات، والأسعار المزدوجة
│   └── users/                # إدارة العملاء والتجار
└── shared/                   # مكونات الواجهة المشتركة (Buttons, Inputs, Badges, Modals...)
```

## 🚀 التشغيل والتطوير المحلي

### 1. تثبيت الاعتماديات
```bash
npm install
```

### 2. تشغيل الفحوصات الآلية (Unit Tests)
```bash
npm test
```
*(تم اجتياز 29 اختبارًا بنجاح يشمل النواة، المتغيرات، التسعير، دورة الطلبات، ودفتر الأستاذ)*

### 3. زرع البيانات الأولية للمتجر (Seeding)
لتعبئة أقسام جاهزة (ألعاب، أدوات، أواني، إكسسوارات) ومنتجات متعددة المتغيرات وحسابات افتراضية:
```bash
npm run seed
```

الحسابات الافتراضية المزروعة:
- **المدير:** `admin` / `AdminPassword123!`
- **التاجر:** `trader_ali` / `TraderPassword123!`
- **العميل:** `salem_customer` / `CustomerPassword123!`

### 4. بناء المشروع للإنتاج
```bash
npm run build
```

### 5. بدء خادم التطوير
```bash
npm run dev
```
افتح المتصفح على: `http://localhost:3000`
